# Fact Bank Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The author's facts live in one hand-written YAML file with four kinds of entry (fields, facts, known answers, stories). A new library checks and loads it, and the runner command `runner facts check` reports on it without ever printing a value.

**Architecture:** A new Nx library, `libs/fact-bank`, holds a strict Zod schema, a YAML reader (failsafe schema, so every value is a string), cross-entry rules (unique ids and facts, placeholders, resume file), and a mapper that turns every problem into a value-free message. It exposes `checkFactBank` (returns a result) and `loadFactBank` (returns the typed bank or throws). The runner adds one subcommand that prints the result. A committed example file is the format's documentation and a test fixture.

**Tech Stack:** Nx 24.0.2, pnpm 12, Node 24, TypeScript (nodenext, strict), Vitest 5, `zod` ^4.6.7 (as 10xjobs), `yaml` ^2.9.0, `tsx` 4.

**Spec:** `docs/superpowers/specs/2026-11-12-fact-bank-design.md`

## Global Constraints

- Branch `feat/slice-04-fact-bank` from `main`. The first commit holds the spec (status changed to `approved`) and this plan. Never work on `main`.
- **Never name the private folder in a Bash command or commit message.** The guard blocks any Bash command whose text contains it. Write `the bank folder` or `the default path` in messages. Source files and docs may contain the string; only commands can't.
- Claude never reads or writes the author's real bank file. All tests use files under `libs/fact-bank/` or a temp dir.
- **No value ever appears in an error, a warning or command output.** Messages name a location (`fields.email`, `facts[3]`, `answers[12] (id: contractor-rate).variants[0].answer`, `line 4, column 7`) and a problem. Zod's own `issue.message` and the `yaml` package's error messages are never passed through.
- Placeholders: exactly `{source}`, `{company}`, `{jobTitle}`. Any other `{…}` in answer or variant text is an error. Stories aren't checked.
- Size warning above `60_000` characters of file text; tokens estimated as `Math.ceil(characters / 4)`. A warning, never an error.
- Ids and tags: kebab-case, `/^[a-z0-9]+(-[a-z0-9]+)*$/`. Ids unique across `answers` and `stories` together.
- Dates (`confirmed`): `YYYY-MM-DD` and a real calendar date.
- Unknown keys are errors at every level.
- No new runtime dependency besides `zod` and `yaml` (in the library). `patchright-core` stays at exactly `1.64.3`.

## Review Focus

1. **An empty list written as `facts:` with nothing after it** (YAML null). Expect the error `facts: must be a list (write [] for none)`, not a type dump. Test in Task 1.
2. **CRLF line endings or a UTF-8 BOM** from a Windows editor. Expect the file to load exactly as the LF version does. Test in Task 2.
3. **Tab indentation**, a common hand-editing slip. Expect one error at a line and column with no snippet of the line. Test in Task 2.
4. **A mistyped value that lands as a key** (`+44 7700900123: x` under `fields`). An unknown-key message names the key only when it looks like an identifier (`/^[A-Za-z][A-Za-z0-9_-]{0,30}$/`); otherwise it says `unknown key`. Test in Task 2.
5. **Two facts that differ only in whitespace** (`I am willing  to relocate.` and `I am willing to relocate. `). Expect a duplicate error. Compare after trimming and collapsing runs of whitespace, case-sensitive. Test in Task 3.

### Task 2: Reading the file, with value-free problems

**Files:**

- Create: `libs/fact-bank/src/read.ts`, `libs/fact-bank/src/problems.ts`
- Test: `libs/fact-bank/src/read.spec.ts`, `libs/fact-bank/src/problems.spec.ts`

**Interfaces:**

- Consumes: `factBankSchema` (Task 1).
- Produces:
  - `interface Problem { where: string; message: string }`;
  - `formatProblem(p: Problem): string` returns `` `${where}: ${message}` ``;
  - `whereOf(path: (string | number)[], raw: unknown): string`, for example `['answers', 12, 'variants', 0, 'answer']` → `answers[12] (id: contractor-rate).variants[0].answer`. The `(id: …)` is added only after an `answers[n]` or `stories[n]` segment whose raw `id` matches `ID_PATTERN`;
  - `problemsFromZod(error: z.ZodError, raw: unknown): Problem[]`, with its own message per issue code: `invalid_type` → `must be a <expected>` (for an array path: `must be a list (write [] for none)`), `unrecognized_keys` → `` unknown key `k` `` per key (or `unknown key` when `k` fails `/^[A-Za-z][A-Za-z0-9_-]{0,30}$/`), missing → `is required`, a format failure → a fixed message per field (`must be an email address`, `must start with + and digits`, `must be digits only`, `must start with https://`, `must be a date written YYYY-MM-DD`, `must be kebab-case`), the answer/variants refinement → `needs exactly one of answer or variants`. Any other code → `is not valid`;
  - `readYaml(text: string): { raw?: unknown; problems: Problem[] }`. It strips a leading BOM, uses `parseDocument(text, { schema: 'failsafe', uniqueKeys: true })`, reports each `doc.errors` entry as `{ where: 'line L, column C', message: 'YAML syntax error' }` (from `error.linePos`), and rejects any anchor or alias (`visit`) with `message: 'YAML anchors and aliases are not allowed'`. `raw` is `doc.toJS()` only when there are no problems.

- [ ] **Step 1: Write the failing tests**
  - `read.spec.ts`:
    - a minimal valid file parses, and `raw.fields.phone.number` is the string `'07700900123'` (the leading zero is kept);
    - `5000`, `Yes` and `2026-10-01` all come back as strings;
    - the same file with CRLF endings and a BOM gives a deep-equal `raw` (Review Focus 2);
    - a duplicate key gives one problem with `where` matching `/^line \d+, column \d+$/`;
    - a tab-indented line gives a problem at a line and column, and `formatProblem` of it doesn't contain the line's text (Review Focus 3);
    - `&a` and `*a` each give the anchors-and-aliases problem.
  - `problems.spec.ts`:
    - `whereOf` returns the example above, and `facts[3]` for a fact;
    - for each failing input from Task 1's tests, run `problemsFromZod`. Expect a message from the fixed list, and expect that no `formatProblem` output contains the bad value (for example `'sam.example.com'`, `'2026-02-30'`, `'http://'`);
    - `facts: null` gives `facts: must be a list (write [] for none)`;
    - an unknown key `answr` gives `` unknown key `answr` ``; the key `'+44 7700900123'` gives `unknown key` without the digits (Review Focus 4).

### Task 3: Cross-entry rules, the resume, and the public API

**Files:**

- Create: `libs/fact-bank/src/rules.ts`, `libs/fact-bank/src/bank.ts`, `libs/fact-bank/src/paths.ts`
- Modify: `libs/fact-bank/src/index.ts`
- Test: `libs/fact-bank/src/rules.spec.ts`, `libs/fact-bank/src/bank.spec.ts`

**Interfaces:**

- Consumes: `factBankSchema`, `FactBankFile`, `PLACEHOLDERS` (Task 1); `readYaml`, `problemsFromZod`, `Problem`, `formatProblem` (Task 2).
- Produces:
  - `crossEntryProblems(file: FactBankFile): Problem[]`:
    - duplicate id across answers and stories → `duplicate id, same as answers[2]`;
    - duplicate fact after trim and whitespace-collapse → `duplicate fact sentence, same as facts[1]`;
    - each `{…}` in an answer's or variant's `answer` that isn't one of `PLACEHOLDERS` → `unknown placeholder (allowed: {source}, {company}, {jobTitle})`.
  - `resumeProblems(resume: string, baseDir: string): Problem[]`, all at `where: 'fields.resume'`:
    - the path resolves outside `baseDir` (absolute, or relative with `..` above it) → `must be inside the bank's folder`;
    - the file doesn't exist → `file not found`;
    - its first 5 bytes aren't `%PDF-` → `is not a PDF`.
  - `interface Fact { text: string; tags: string[]; confirmed?: string }`.
  - `interface FactBank`: `FactBankFile` with `facts: Fact[]`, `phone.number` with spaces removed, `fields.resume` as an absolute path, and the derived `fields.fullName` (`first last`), `fields.location` (`city, country`), `fields.phone.full` (`countryCode number`).
  - `interface CheckResult { path: string; ok: boolean; counts: { facts: number; answers: number; stories: number }; size: { characters: number; tokens: number }; warnings: Problem[]; errors: Problem[]; bank?: FactBank }`.
  - `DEFAULT_FACT_BANK_PATH`: the repo root (three levels up from `paths.ts`, so the same from `src/` and `dist/`) joined with the default path from the spec. `SIZE_WARNING_CHARACTERS = 60_000`.
  - `checkFactBank(path = DEFAULT_FACT_BANK_PATH): CheckResult`. A missing file gives one error `{ where: 'file', message: 'not found' }`.
  - `class FactBankError extends Error { problems: Problem[] }`, whose `message` is the `formatProblem` lines joined by newlines.
  - `loadFactBank(path = DEFAULT_FACT_BANK_PATH): FactBank`. It throws `FactBankError` when the check isn't `ok`, and ignores warnings.

    - duplicate fact, including the whitespace pair from Review Focus 5;
    - `'{ source }'` and `'{Source}'` are rejected and `'{source}'` passes;
    - a story containing `{x}` gives no problem.
  - `bank.spec.ts`: write files into a temp dir (`mkdtempSync`):
    - a valid file plus a `resume.pdf` holding `%PDF-1.4\n%%EOF\n` gives `ok: true`, the counts, `size.characters === text.length`, `size.tokens === Math.ceil(text.length / 4)`, `bank.fields.fullName === 'Sam Example'`, `bank.facts[0]` normalized to `{ text, tags: [] }`, and an absolute `bank.fields.resume`;

    - `loadFactBank` on a broken file throws `FactBankError`, and its message holds no value from the file;
    - `checkFactBank` on a missing path gives `file: not found`;
